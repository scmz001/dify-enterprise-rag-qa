# 星辰科技企业制度问答系统（Dify 版）

## 一、项目简介

这是之前 Streamlit 版的迁移版，搬到 Dify 上做成低代码 RAG。相比原版，主要多了三块：

- 关键词提取节点（提升脏查询的检索命中）
- 混合检索（语义 + 关键词）
- 100 条分层自动化评测体系

当前配置：关键词提取 `qwen2.5:7b-instruct`，回答 `qwen3.5-9b`（关闭思考）。本地部署，数据不出内网。

---

## 二、流程

```
用户输入
   ↓
关键词提取（qwen2.5:7b-instruct）
   ↓
知识检索（混合检索：语义 0.7 / 关键词 0.3，Top-K=6，阈值 0.4）
   ↓
代码节点（判断 result 是否为空，输出布尔值 has_result）
   ↓
条件分支（has_result 是否为 true）
   ├── true  → 模板转换 → 回答生成（qwen3.5-9b，关闭思考模式）
   └── false → 固定拒答（不调用模型）
                 ↓
               输出
```

关键词提取负责从问题里抽检索词；知识检索召回相关文本块；代码节点判断检索结果是否为空；条件分支决定走生成还是拒答。

---

## 三、Dify 配置

- **知识库**：14 份文档，通用分块（`\n\n`，1024 字，重叠 100 字）
- **模型**：回答 qwen3.5-9b（关闭思考模式）；关键词提取 qwen2.5:7b-instruct
- **检索**：混合检索，语义 0.7 / 关键词 0.3，Top-K=6，阈值 0.4
- **无 Rerank**：曾配置 Qwen3-Reranker-8B，因 rerank-adapter 返回假分（全 0.5）而放弃，改用混合检索权重模式等效降级

## 四、评测体系

| 文件 | 用途 |
| :--- | :--- |
| `test_cases.csv` | 100 条分层测试集（单跳 30 / 多跳 20 / 对比 10 / 拒答 20 / 诱导 10 / 异常 10） |
| `scripts/run_evaluation.py` | 自动化评测脚本，逐条调用 Dify API，按关键词 + 行为判定打分 |
| `results.xlsx` | **最新一次**运行结果，每次覆盖 |
| `results/` | 历史归档，命名 `results_<时间戳>_<版本号>_kw-<关键词模型>_ans-<回答模型>.xlsx` |

脚本每次运行会打印「本次 vs 上次」摘要（总通过率、分类型通过率、回归项、改进项、成本对比）。

### 关键版本详解

<details>
<summary><b>v0.10：一条多余的连线毁掉整个分支逻辑</b></summary>

**现象**：28 条请求返回 HTTP 400，报错 `Variable #1791738139021.output# not found`。

**定位**：Dify 把空数组 `[]` 判为"非空"，检索为空时仍走向 LLM 分支，而 LLM 引用的模板转换变量不存在。

**处理**：
1. 条件分支前加代码节点，输出布尔值 `has_result`
2. 条件分支改为判断 `has_result == false`
3. **删除 `知识检索 → 回答LLM` 直接连线**（关键：这条线绕过了条件分支）
4. 交换 IF/ELSE 连线方向

**结果**：28 条 HTTP 400 消失，拒答题 40% → 100%。

</details>

<details>
<summary><b>v0.15：从"改模型/检索"转向"改数据本身"（收益最大单点）</b></summary>

**背景**：检索日志显示，"标题块"和"正文块"被 `\n\n` 切成两块，`content` 只有标题没有正文。做了三轮处理：

1. 用 AI 工具将 14 份原始文档统一转 Markdown（OCR 修正 + 全角标点 + 标题层级规范化）
2. 删除 H2/H3 标题与其下方第一行正文之间的空行（66 处）
3. 删除"引导句（冒号结尾）+ 列表"之间的空行（32 处）

**验证**：非空行差异为 0，只删空行不改文字；66/66 H2 标题紧贴正文。

**结果**：通过率 91% → 97%；对比题 70% → 100%；上轮 6 条失败全部修复。

</details>

### 一些经验

1. **调数据比调模型有用。**  
   45% 到 97% 的提升里，大约 11 个点来自分块重建、文档规范化和并列段落合并；v0.1–v0.5、v0.11 换模型基本没带来收益。效果差的时候，先看文档解析和分块，别急着换大模型。

2. **回答模型的影响远大于关键词提取模型。**  
   8 组对比里，换关键词提取模型通过率最多波动 2pt，换回答模型波动能到 11pt。资源有限时先保回答模型质量；关键词提取 7B 就够，不必上 9B 或 14B。

3. **模型能力有跳变，不是线性的。**  
   qwen3-8b 到 qwen3.5-9b 只多 1B 参数，但拒答类通过率从 85% 跳到 100%、多跳从 95% 跳到 100%。不要只看参数规模判断够不够用，必须实测。

4. **Dify 分支异常，先看连线。**  
   v0.10 里，“知识检索 → 回答LLM”这条直接连线看起来只是提供上下文，实际绕过了 IF/ELSE，导致 ELSE 分支下回答节点仍被执行。排查时不要只盯节点配置。

5. **低代码平台的自动机制会生效。**  
   Dify 内置记忆会强制把每轮的 `sys.query` 注入下游节点，即使用户在节点上自定义了输入。v0.7 中，回答节点本来只该看到关键词提取输出，却因记忆被追加了原始问题。用低代码平台时，最好逐节点打印真实输入输出。

6. **分块策略要按文档结构来。**  
   父子分块常被推荐，但更适合长段落、章节边界模糊的文档。本项目是“短章节 + 结构化条款”，父子分块会导致父块只剩标题、正文全在子块，检索命中空标题。最后用通用分块更合适。

7. **评测脚本本身也要迭代。**  
   v0.12 修测试集设计缺陷；v0.13 引入归一化匹配 + 分层降级 + 行为判定，把假失败从 15% 降到 6%；v0.17 引入“API 契约豁免”，空输入属接口层拒绝，不该计失败。一个 RAG 项目的分数有多可信，取决于能不能区分“模型答错”和“评测口径错”。

8. **离线重算让口径修正和能力改进分开。**  
   评分规则变化时，用 `recalc_results.py` 对已存档的模型回答重跑打分。这样 v0.13 的 +6pt（口径修正）和 v0.15 的 +6pt（真实能力提升）能独立归因。没有这个机制，很容易误以为通过率上升就是模型变强了。

## 六、通过率与成本分析

### 通过率构成

**v0.18 配置**：关键词提取 qwen2.5:7b + 回答 qwen3.5-9b（关闭思考），100 条里 99 条通过，唯一失败是 #92（纯空白输入，模型幻觉）。

**构成对比**：

| 项目 | v0.17（qwen2.5-14b + GLM-4-9B） | v0.18（qwen3.5-9b + qwen2.5:7b） |
| :--- | :-: | :-: |
| 总通过率 | 100% | 99% |
| LLM 真实作答 | 84 条 | 83 条 |
| 固定回复节点保底 | 15 条 | 15 条 |
| 脚本契约豁免 | 1 条（#91 空输入） | 1 条（#91 空输入） |
| 失败项 | 无 | #92 空输入幻觉 |

**严格模式校验**（`--match-mode all`，正向题 60 条）：

| 配置 | 通过数 | 通过率 |
| :--- | :-: | :-: |
| v0.17 | 56/60 | 93.3% |
| v0.18 | 55/60 | 91.7% |

这是"真实 RAG 能力"的下限估计。回答模型换小后，严格模式下多损失 1 条，可接受。

## 七、未完成项

原始规划有 5 个阶段：

| 阶段 | 状态 | 说明 |
| :--- | :--- | :--- |
| 一、平台迁移 |  完成 | Streamlit → Dify |
| 一、数据扩展 |  未做 | 仍为 14 份文档，未扩到 50-80 份 |
| 二、多轮对话 |  放弃 | Dify 内置记忆强制注入 sys.query，污染生成 |
| 三、Rerank |  放弃 | 本地 rerank 服务不可用，云端会引入数据出内网风险 |
| 四、100 条评测 |  超额完成 | 6 类 100 条，脚本经历 3 轮迭代 |
| 五、成本估算 |  完成 | 见第六章 |

两个主动放弃的决策依据：

1. **多轮对话**：Dify 内置记忆无法关闭对下游节点的强制注入，自建会话变量成本高于收益；单领域问答用户追问占比低。
2. **Rerank**：混合检索的关键词权重（0.3）是等效降级方案，配合 Top-K 3→6 + 阈值 0.5→0.4 补偿召回。

## 八、与 Streamlit 版的对比

| 维度 | Streamlit 版 | Dify 版（本项目） |
| --- | --- | --- |
| 部署方式 | 本地 Python 进程 + LM Studio Local Server | Dify 平台（`localhost/v1`）承载应用与知识库 |
| 编排方式 | 代码编排（LangChain） | 可视化 Chatflow |
| 多轮对话 | 不支持 | 支持（会话变量，但本项目未启用） |
| 检索策略 | 纯向量（ChromaDB + bge-m3），阈值 0.55，Top-K=4 | 混合检索（语义 0.7 / 关键词 0.3），Top-K=6，阈值 0.4 |
| 评测方式 | 人工验收（`--demo` 4 问题 + 界面抽查） | 100 条分层自动评测 |
| 模型切换 | 改 `.env` 重启进程 + LM Studio 换模型 | Dify 界面切换，即时生效 |

Streamlit 版逻辑透明、便于逐行调试；Dify 版迭代快、可对外分享链接演示，但细节沉在平台配置里。
